# 05 · 导航系统闭环：MATLAB 仿真 vs ROS2 实际部署

> 回答核心疑问：MATLAB 仿真和实际部署到底差在哪？真做导航是怎么跑的？
> 这是从"算法认知"到"应用认知"的最后一跃。

## 一、你的疑问的完整回答

### "路径规划算法用 MATLAB 仿真居多，但实际部署怎么运行？"

**答案**：
1. **MATLAB 是"算法实验室"**——验证算法（数学正确性、参数、可视化）
2. **实际部署是"系统集成"**——Nav2 是标准框架，算法只是零件
3. **从 MATLAB 到部署** = 从"验证算法"到"跑通系统"的跨越

### MATLAB 到底怎么用（科研角色）

| 用途 | 说明 |
|---|---|
| **算法验证** | 用 Toolbox 快速验证新算法/参数 |
| **数学分析** | 矩阵运算、可视化方便（科研论文常用）|
| **MATLAB-ROS 集成** | 设计算法 → 生成 ROS 节点（Toolbox 支持）|
| **对比基准** | 同一算法 MATLAB vs 手写验证 |

**为什么科研用 MATLAB**：
- 算法开发周期快（不用编译，矩阵即算即得）
- 画图/可视化专业（论文插图）
- 数学库完善（优化、控制、信号）

## 三、完整导航系统（ROS2/Nav2）怎么运行

### 实际部署（不是"跑个算法"，是"跑系统"）

```
┌─ 传感器 ─────────────────────────────┐
│ 激光雷达 → 扫描数据 (/scan)          │
│ 里程计 → 运动信息 (/odom)            │
├─ 建图与定位 ────────────────────────┤
│ SLAM (slam_toolbox) → 地图           │
│ AMCL → 位姿 (/amcl_pose)             │
├─ 规划 ──────────────────────────────┤
│ Nav2 全局规划器 (A*) → 全局路径       │
│ Nav2 局部规划器 (DWA) → 速度指令      │
├─ 控制 ──────────────────────────────┤
│ 底盘控制器 → /cmd_vel → 电机         │
└─────────────────────────────────────┘
```

### 关键：节点化 + 话题通信
```
ROS2 里每个功能是一个"节点"，通过"话题"通信：
/scan（激光） → slam（建图） → /map（地图）
/map + /odom → amcl（定位） → /amcl_pose（位姿）
目标点 → nav2（规划） → /cmd_vel（速度） → 底盘
```

## 四、MATLAB 仿真 vs ROS2 部署对比（本质）

| 维度 | MATLAB | ROS2/Nav2 |
|---|---|---|
| 目的 | 算法验证 | 系统部署 |
| 数据 | 理想/仿真 | 真实传感器 |
| 地图 | 已知数组 | 实时构建 |
| 定位 | 假设 | AMCL 实时 |
| 输出 | 路径图 | 控制指令 |
| 硬件 | 无 | 底盘/电机 |
| 多节点 | 单机 | 分布式 |
| 实时性 | 无硬要求 | 必须实时 |

**核心**：MATLAB 让你"验证算法能工作"，ROS2 让你"让机器人真的动"。
