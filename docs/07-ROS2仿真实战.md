# 07 · ROS2 仿真实战：Gazebo 建图 → Nav2 导航

> 手写算法（A*/RRT*/DWA）在纯 Python 里验证后，在 **Ubuntu + ROS2 Humble + Gazebo + Nav2** 仿真环境完整跑通。
> 这一步把「算法理解」变成「系统落地能力」。

## 一、总体流程

```
手写算法库（已完成）→ 仿真验证（Gazebo + Nav2）→ 实机（LEAP 小车）
                     ↑ 本文档：Ubuntu 仿真全流程
```

四步：
1. **Gazebo** 启动 `turtlebot3_world` 迷宫世界 + burger 小车
2. **Cartographer** SLAM 建图（自动探索遍历迷宫）
3. **保存地图**（room.pgm + room.yaml）
4. **Nav2** 加载地图，AMCL 定位，自主导航到达目标点

## 二、环境（Ubuntu 22.04 + ROS2 Humble）

| 组件 | 安装 |
|---|---|
| Gazebo Classic | 11.10.2（`ros-humble-gazebo-ros-pkgs`） |
| TurtleBot3 | `ros-humble-turtlebot3 turtlebot3-simulations turtlebot3-cartographer turtlebot3-navigation2 turtlebot3-teleop` |
| Nav2 | `ros-humble-nav2-bringup navigation2` |

```bash
export TURTLEBOT3_MODEL=burger   # 写入 ~/.bashrc
```

## 三、执行步骤

### 1. 启动 Gazebo 世界

```bash
ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py
```

### 2. Cartographer 建图

```bash
ros2 launch turtlebot3_cartographer cartographer.launch.py use_sim_time:=True
```

自动探索建图（本项目新增 `robot/explore_laser.py`，基于激光的墙壁跟随/避障）：

```bash
python3 robot/explore_laser.py 90   # 每轮 90 秒，多轮覆盖
```

### 3. 保存地图

```bash
mkdir -p ~/map
# 订阅 /map 话题保存为 room.pgm + room.yaml（见 robot/save_map.py）
```

### 4. Nav2 导航

```bash
ros2 launch turtlebot3_navigation2 navigation2.launch.py map:=~/map/room.yaml use_sim_time:=True
python3 robot/nav_goal.py 1.5 1.5   # 目标点 (x, y)
```

> 注：`robot/nav_goal.py` 封装了「初始位姿 + 等待 Nav2 激活 + 发送目标 + 监控到达」。

## 四、踩坑记录：ROS2 QoS 兼容性（本项目的核心收获）

仿真过程中解决了 **3 处 QoS 不兼容**，这是 ROS2 仿真最常见的坑，值得记录：

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | Cartographer 一直报 `Queue waiting for data: (0, scan)`，收不到雷达 | gazebo 激光插件以 **RELIABLE** 发布 `/scan`，而 cartographer 以 **BEST_EFFORT** 订阅，二者不兼容 | 修改 `turtlebot3_burger/model.sdf`，给激光插件加 `<qos>` 配置，让 gazebo 原生以 BEST_EFFORT 发布 |
| 2 | gzserver 崩溃：`InvalidQoSException: 'keep_last' used without providing a depth` | SDF 里 `<history>` 的 `depth` 必须是**属性**（`<history depth="10">`）而不是独立 `<depth>` 元素 | 修正 SDF 格式 |
| 3 | Nav2 收不到初始位姿（AMCL 提示 "Please set the initial pose"） | AMCL 以 **BEST_EFFORT** 订阅 `/initialpose`，而 `ros2 topic pub` / simple_commander 默认 RELIABLE 发布 | 自定义 BEST_EFFORT 发布器发送初始位姿（`nav_goal.py` 中已封装） |

**SDF QoS 配置格式**（Gazebo 插件原生指定 QoS）：

```xml
<plugin name="turtlebot3_laserscan" filename="libgazebo_ros_ray_sensor.so">
  <ros>
    <remapping>~/out:=scan</remapping>
    <qos>
      <topic name="scan">
        <publisher>
          <reliability>best_effort</reliability>
          <history depth="10">keep_last</history>
        </publisher>
      </topic>
    </qos>
  </ros>
</plugin>
```

## 六、手写算法 vs Nav2（对照）

| 维度 | 手写库（本项目） | Nav2 |
|---|---|---|
| 全局规划 | A* / RRT* / Informed RRT* | NavFn / Smac Planner（Theta* / Hybrid-A*) |
| 局部规划 | DWA（实时避障） | DWB / Regulated Pure Pursuit |
| 定位 | 无（假设已知位姿） | AMCL（概率定位） |
| 建图 | 无（输入固定地图） | Cartographer / SLAM Toolbox |
| 接口 | 统一 `create_planner` | ROS2 Action（`NavigateToPose`） |
| 生产级 | ✗（教学/研究） | ✓（工业标准） |

**意义**：手写算法证明了**原理理解**（能实现、能调参、能跑通），Nav2 证明了**系统集成**（能部署、能定位、能避障）。两者互补。
