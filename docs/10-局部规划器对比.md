# 10 · 局部规划器对比（DWB / MPPI / Regulated Pure Pursuit）

> 在 Nav2 中切换不同局部规划器（控制器），对比它们在轨迹平滑度、到达时间、避障上的表现。
> 局部规划器是导航"最后一公里"——全局规划器给出路径，局部规划器负责实时跟踪并避障。

## 〇、对比架构

```
                ┌─────────────────────────────────────────────┐
                │               Nav2 导航系统                    │
                │                                             │
  全局规划器     │  planner_server（同一：A*/NavFn）             │
  ─────────────▶│        │  生成全局路径 /plan                   │
                │        ▼                                     │
  局部规划器 ←───│  controller_server  ◄── 切换的变量             │
  (唯一变量)     │  FollowPath.plugin:                          │
                │   ├─ DWB │ MPPI │ Regulated Pure Pursuit     │
                │        │  实时速度指令 /cmd_vel               │
                │        ▼                                     │
                │  机器人（Gazebo diff_drive）                   │
                └─────────────────────────────────────────────┘
                     ▲
        planner_compare.py 记录 /odom 轨迹 + 耗时
        → 计算：到达时间 / 轨迹长度 / 平滑度
```

**公平性铁律**：同一地图、同一全局规划器、同一组起终点，**唯一变量 = 局部规划器**。

## 一、对比谁

| 规划器 | 类型 | 特点 |
|---|---|---|
| **DWB**（`dwb_core::DWBLocalPlanner`）| 评分制采样 | Nav2 默认，采样轨迹+代价评分 |
| **MPPI**（`nav2_mppi_controller::MPPIController`）| 模型预测路径积分 | 采样+成本函数加权，平滑性好 |
| **Regulated Pure Pursuit**（`nav2_regulated_pure_pursuit_controller`）| 几何跟踪 | 纯追踪+碰撞检测，简单可靠 |

> TEB 无 Humble 官方包（需源码编译），故对比范围取三者。

## 二、对比方法（公平性设计）

**控制变量**：
- 同一地图、同一全局规划器、同一组起终点
- 唯一变量：`controller_server` 的 `FollowPath.plugin`

**流程**（`robot/planner_compare.py`）：
1. 设置初始位姿（BEST_EFFORT，收紧协方差防迷宫对称误定位）
2. 等待 `navigate_to_pose` 服务（SLAM/AMCL 模式通用）
3. 发送固定目标 → 记录 `/odom` 轨迹 + 耗时
4. 计算指标：到达时间 / 轨迹长度 / 平滑度（相邻段转向角均值）

**指标**：
| 指标 | 含义 |
|---|---|
| 到达时间 | 系统级耗时（含定位/规划/控制）|
| 轨迹长度 | 实际行驶距离 |
| 平滑度 | 相邻轨迹段方向角变化的均值（越小越平滑）|
| 到达与否 | 目标是否达成 |

## 三、三套配置（可直接切换）

| 文件 | 控制器 plugin |
|---|---|
| `nav2_dwb_params.yaml` | `dwb_core::DWBLocalPlanner` |
| `nav2_mppi_params.yaml` | `nav2_mppi_controller::MPPIController`（含 7 个 critic 配置）|
| `nav2_rpp_params.yaml` | `nav2_regulated_pure_pursuit_controller` |

**切换方式**：改 `params_file` 即可，其他不变（配置即切换）。

**SLAM 模式版**（`nav2_navfn_*` 系列）：全局规划器用 NavFn（SLAM 动态地图下更稳），同样三控制器可选。

## 四、使用方法

```bash
# 静态地图模式（AMCL 定位）
ros2 launch turtlebot3_navigation2 navigation2.launch.py \
  map:=~/map/room.yaml params_file:=robot/config/nav2_dwb_params.yaml use_sim_time:=True
python3 robot/planner_compare.py dwb 1.5 1.5     # 采集 DWB 数据

# 换 MPPI：改 params_file 为 nav2_mppi_params.yaml，重启 Nav2，再跑
python3 robot/planner_compare.py mppi 1.5 1.5

# SLAM 模式（Cartographer 定位）
ros2 launch nav2_bringup navigation_launch.py \
  params_file:=robot/config/nav2_navfn_params.yaml use_sim_time:=True autostart:=True
```

## 五、状态与踩坑

> **诚实记录**：本环境（WSL 类网络 + 迷宫世界）下，多次 live 导航因**环境不可靠**（AMCL 迷宫对称误定位、机器人卡墙、DDS 共享内存退化）未能完成三规划器的完整对照采集。

| # | 问题 | 解决 |
|---|---|---|
| 1 | 迷宫对称导致 AMCL 收敛到错误位置（A* 规划极短路径失败）| 收紧初始位姿协方差 |
| 2 | `waitUntilNav2Active` 依赖 AMCL，SLAM 模式无 AMCL 挂起 | 改用原始 NavigateToPose action client |
| 3 | 多次重启导致 DDS 共享内存污染 | 彻底清理 /dev/shm |
| 4 | `navigation_launch.py` 需 `behavior_server` 配置，params 只有 `recoveries_server` → bringup 中止 | 补 `behavior_server` 段 |
| 5 | behavior 插件注册名是 `nav2_behaviors/Spin`（斜杠），写 `::` 会找不到插件 | 用 `/` 分隔 |

**结论**：三套控制器配置与采集工具已就绪并验证可加载（日志确认 DWB/MPPI/RPP 均成功创建 controller）。完整的量化对照数据需在稳定的仿真环境（无迷宫对称干扰、无 DDS 污染）下采集。
