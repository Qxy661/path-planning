# 04 · SLAM 建图与定位

> 从"规划算法"到"导航系统"的关键一环：建图(SLAM) 和定位(AMCL)。
> 没有地图和定位，全局规划无法工作。
> 配套：TurtleBot3 巡检项目（Gazebo 仿真）。

## 一、为什么需要建图和定位

```
规划算法（A*）假设：我有地图 + 我知道自己在哪
但真实机器人：
  1. 没有地图 → 需要 SLAM 建图
  2. 不知道自己在哪 → 需要定位
```

**导航闭环的完整前提**：
```
建图(有地图) → 定位(知道我在哪) → 规划(怎么走) → 控制(执行)
```

## 二、SLAM（Simultaneous Localization And Mapping）

### 问题
**同时建图 + 定位**：机器人边移动边建地图，同时要知道自己在地图哪里。
（鸡生蛋问题：定位需要地图，建图需要定位）

### 方案（2D 激光 SLAM）
| 方法 | 原理 | 特点 |
|---|---|---|
| **slam_toolbox** | 激光扫描匹配（在线）| 轻量，入门 |
| **Cartographer** | 子图 + 闭环优化（Google）| 更准，较重 |

### 栅格地图（Occupancy Grid Map）
```
地图表示：栅格，每个格子 0-1 表示占用概率
0 = 空闲，1 = 占用，0.5 = 未知
```

**SLAM 输出**：栅格地图（PGM 图像 + YAML 配置）

## 三、AMCL 定位

### 问题
**有了地图，怎么知道"我在哪"？**（GPS 室内不可用）

### 方案：AMCL（Adaptive Monte Carlo Localization）
**粒子滤波**定位：
```
1. 撒一堆粒子（每个粒子 = 一个可能的位置姿态）
2. 每个粒子预测移动（运动模型）
3. 激光扫描匹配地图，给粒子打分（观测模型）
4. 重采样：留下高分粒子（收敛到真实位置）
```

### 为什么粒子滤波
- 非高斯、多峰（位置不确定）→ 粒子比卡尔曼灵活
- 自适应粒子数（收敛后减少，省计算）

## 四、完整导航流程（TurtleBot3 巡检）

### 阶段1：建图
```
启动 Gazebo → 启动 SLAM → 遥控小车走一圈 → 保存地图
```

### 阶段2：定位 + 导航
```
加载地图 → AMCL 定位 → Nav2 启动
→ 点目标 → 全局A* → 局部DWA → 小车自主到达
```

## 五、SLAM 与规划的关系（体系认知）

```
SLAM 建图 → 提供"地图"给规划器
AMCL 定位 → 提供"起点"给规划器
A* 全局   → 在图上规划路径
DWA 局部  → 实时避障
```

**关键**：规划算法（A*/DWA）是"纯算法"，但**没有 SLAM/AMCL 提供输入，它们无法工作**。
这就是"算法认知 → 体系认知"的跨越——懂每个算法，更懂它们怎么组成系统。

## 六、科研/工程要点

1. **SLAM 质量影响导航**：地图不准 → 规划路径可能撞墙
2. **定位漂移**：长时间运行，AMCL 可能发散 → 需重定位
3. **代价地图**：Nav2 在地图上叠加障碍膨胀（机器人半径），避免规划路径太靠近障碍
4. **动态环境**：SLAM 静态假设 vs 真实动态障碍 → 局部规划补充

## 探究练习

1. 为什么"同时"建图和定位是难题？（鸡生蛋）
2. AMCL 粒子滤波怎么从"撒一片"收敛到"一个位置"？
3. 地图不准确（有误差）时，A* 规划的路径会怎样？
